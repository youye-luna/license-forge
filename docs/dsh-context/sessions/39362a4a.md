## 过程中确立的硬性规则与工程约定

1. **未经用户明确指令禁止一切对外写操作**（Turn 27 立规）：不得 `git push`、不得 `gh release create/edit/upload/delete`，本地改动/测试/构建/打包照常，发布前必须先问。（Turn 34 后仍保持"问一句再发"。）
2. **版本号策略**：发行版长期固定在 `0.1.0`，小改动直接覆盖同一发行版与标签，只有出现大改动才递增版本号（Turn 27 + Turn 75 明确定为项目约定，写入 README 维护说明与 `src/lib/ui.ts` 注释）。
3. **只用现行 SPDX 标识符**：废弃写法（如 `GPL-3.0`、`GPL-2.0+`）标为"旧名字（已废弃）"；GPL 家族必须显式区分 `-only` / `-or-later`。项目自身许可即采用 `GPL-3.0-or-later` 而非 `GPL-3.0`。
4. **正文逐字不改（"非必要不改，人怎么搞的就怎么来"）**：只替换许可证作者自己留给使用者的占位符（每处都填但只填主体名称）；作者没留位置的一个字都不加（Apache-2.0、MPL-2.0、Zlib、Unlicense、CC0 等）；示例段（GPL "How to Apply"）、写给读者的说明、正文引用的定义变量一律原样保留。
5. **不自造法律声明**：只有 6 个 GNU 许可证有官方 per-file 模板，其余用 SPDX/REUSE 两行式；官方文件头模板优先于自写声明（93 个许可证自带）。
6. **Apache-2.0 的 NOTICE 无法关闭**（§4(d) 硬性义务）。
7. **术语与可读性**：界面文案走大白话，专业术语必须配白话解释或收进可展开区；禁止出现未解释的 `SBOM`、`官方文件头` 等行话。
8. **诚实标注原则**：推断值必须标注"由正文推断，非权威认定"，并区分三级可信度（精校 32 / ChooseALicense 上游标注 47 / 正则推断）；不确定的判定原样保留（OSADL 的 `Unknown`、`Check dependency` 不改写成确定）。
9. **商标默认写"不授权"**：ChooseALicense 的 `trademark-use` 语义是"明确声明不授予商标权"，没有这句的实质上也不授权，不得写"没提到"。
10. **中文覆盖的措辞**：没有中文出处时写"本站未收录该许可的中文文本"，**禁止**断言"该许可没有中文版本"（有用例断言禁止）。
11. **分类标签统一**：用"宽松型 / 公共领域型 / 著作权型（文件级·整个项目·含网络使用）/ 内容与数据型 / 非开源型 / 未能判定"，下拉与详情面板共用同一份 `FAMILY_LABEL`。
12. **背书与商标必须分开判定**：只认"名字 + endorse/promote 同现"的句式；Apache-2.0 有商标条款但不禁止背书，必须有测试守住这一点。
13. **不合并上游"同键不同文"**（Turn 58 明令）：`linum`、`ms-refl`、`ralf-corsepius`、fuchsia/fuschia 等 ScanCode 内部同文不同名条目保持分开登记；反过来 `-en` 这类英文单语副本属于真重复，必须剔除。
14. **LICENSES/ 目录下的文件名不带扩展名**（用户决定，偏离 REUSE 3.0）：必须在界面文案里写明这会令 `reuse lint` 报不合规。
15. **绝不用 PowerShell 读写源码文件**：一律用 `edit` 工具或 node 脚本（Turn 23 事故后成为项目文档里的硬约定）。
16. **数据加工不变量**：逐条精校值与推导值的分歧必须逐条登记理由，且白名单里不允许出现已不再分歧的条目。
17. **README 测试表必须列全 `test` 脚本涉及的每个测试文件**（防漂移测试）。
18. **测试/构建纪律**：每次改动跑 `pnpm test` + `tsc --noEmit` + `next build --webpack`；打包后可下载复验 SHA256 必须本地 = 远端。
19. **`build` 固定用 `--webpack`**（Turbopack 无法处理非 ASCII 目录下的 pnpm 联接布局）；TypeScript 固定 5.9。
20. **发行说明从简**（Turn 34），只保留必要信息。
21. **打包产物路径必须为正斜杠**，`release/` 下的文档与配置必须受 git 跟踪（`dist/` 被忽略）。
22. **启动脚本不许回到包内**、`web.config` 不许出现 `rewrite` / `httpCompression` / `requestFiltering` 属性写法（有测试断言，断言前先剥离 XML 注释）。
23. **单人项目可强制移动 `v0.1.0` 标签**，但一旦有第二个贡献者就改为每次发布递增版本号（写入 README 维护须知）。

## 踩过的坑与教训

1. **PowerShell 读写源码会静默毁文件**：`Get-Content | Set-Content` 往返既加 BOM（SWC 认不出 `'use client'`，客户端组件掉出 manifest）又按 ANSI/GBK 误解码 UTF-8（`'数据'` → 乱码）。后续在 Turn 68/69 又复发两次：`package.json` 的 `description` 被写坏并**已提交进仓库**、JSON 解析失败被迫 `git checkout` 回滚。教训：本项目禁止用 PowerShell 读改写源码，改用 `edit`/node，并加"全仓库编码损坏扫描"测试（豁免 `public/data/` 上游语料与测试文件自身）。
2. **模块名 `sort.ts` 会让 `next build --webpack` 失败**，报错却指向未被修改的 `Generator.tsx`（"Could not find the module ... in the React Client Manifest"），改名 `ordering.ts` 即恢复。机制未查明，用测试把文件名钉死。
3. **`Compress-Archive` 写出反斜杠 entry 路径**（`data\license-index.json`），Windows 解压正常但 Linux `unzip` 解出一堆怪文件名，站点跑不起来；改为自写 `scripts/package.mjs` 显式转换并自检。
4. **`file://` 双击打不开**：资源是绝对路径（可改相对）+ 数据用 `fetch()` 拉取，`file://` 下 origin 为 `null`，浏览器直接拒绝跨源 fetch —— **改相对路径解决不了**，只能起本地服务器（最终提供启动脚本，后又按用户要求删除）。
5. **IIS 部署两个硬约束**：站点必须建在根路径（子路径下 `/_next/...` 全 404，`web.config` 修不了）；缺 `.json`/`.mjs`/`.txt` MIME 映射会被拒绝应用。`web.config` 里写 `rewrite` 会因缺 URL Rewrite 模块报 **500.21**，`requestFiltering` 属性写法报 **500.0**，比不写更糟。
6. **`.cmd` 不能含非 ASCII 字节**：cmd.exe 按控制台代码页解析批处理，UTF-8 中文会误解码甚至中断解析（第一版混入全角破折号 `—`）。
7. **Git/GitHub 环境坑**：`github.com:443` 直连不通（首次推送超时、仓库建好却是空的），需给 git 配**只对 github.com 生效**的代理 `http://127.0.0.1:7897`；`.npmrc` 含本机绝对路径需 gitignore 并提交 `.npmrc.example`；`core.autocrlf` 会破坏"LICENSE 逐字节等于工具输出"的性质，需 `.gitattributes` 锁 LF。
8. **数据加工陷阱**：`patent-use` 同名反义（permissions 里是授予、limitations 里是不授予）；站内 404 返回 9 KB HTML 错误页被当成许可证正文（需按内容嗅探）；`GPL-3.0` 与 `GPL-3.0-only` 不做后缀规范化就整族对不上；占位符有 5 种以上形态（尖括号、大写尖括号、方括号、裸大写词、裸小写词、下划线），且探测范围必须严格限定在含 `Copyright` 的行，否则 BSD 免责声明里的 "THE AUTHOR" 会大量误报。
9. **推断规则的多次误判**：MPL 被误判有网络触发（3.2 节 "available over a network" 恰恰是**不**触发）；`Affero` 不能当网络著佐权标志（GPL-3.0 与 MPL 正文都提到它）；MPL 正文的**局部**专利排除被正则判成"明确不授权"（上游标注是授予）；CC-BY/OFL 的禁背书措辞不含 `name` 字样、OFL 写作 `promote, endorse or advertise`（顺序不同）导致漏判；EUPL 被凭印象断言"没有网络条款"（实际有 `network-use-disclose`）。
10. **中文继承的幽灵数据**：把哈希表的 `undefined` 当 Map 键，导致"中文入口 742 个"、`GPL-3.0-or-later` 继承了 `MulanPSL-2.0` 的链接。改为正文取不到就跳过，并用归一化正文哈希继承（而不是按名字猜变体）。
11. **逐条精校值没进上游 family 数据**，导致列表与详情对不上（AGPL 列表归"整个项目"、详情显示"含网络使用"）；修法是让手动值显式生效（32 个零冲突）。
12. **静默丢字段的真 bug**：`LicenseFacts` 是手写枚举字段，新增 `endorsement` / `includeCopyright` 时忘了加进接口，赋值被静默挡住，`resolveSpec` 产出的 spec 上没有这两个字段 —— 于是上一轮的"保留版权声明"在详情面板一直失效、BSD-3-Clause 显示"正文没写"。而验证脚本**直接调 `deriveFacts` 绕过了出错路径**。修法：接口补字段、`spec.ts` 改为 `...facts` 整体透传、加"用长尾条目比对 `resolveSpec` 与 `deriveFacts` 每一项"的守护测试。
13. **`navigator.clipboard` 只在安全上下文可用**：IIS 普通 HTTP 下为 `undefined`，而代码 `catch` 吞掉错误 —— 按钮点了毫无反应也不报错。改为 `execCommand` 兜底 + 失败可见提示。
14. **版本与标签反复**：先发 v0.1.0 → 建 v0.1.1 → 用户要求回退 0.1.0 并删 v0.1.1（release 与 tag 都下线）→ 之后固定 0.1.0 覆盖上传。还发现**标签停在 18 个提交之前**："压缩包是新的、源码快照链接是旧的"，只能强制移动标签。
15. **被否掉/回退的方案**：把"落空项扣 60 分"（过度纠正，把 OFL 在字体场景扣成负分、排到 CC-BY 之后，最终回到命中计分只修文案）；合并 ScanCode 内部同文不同名条目（用户明确否决）；包内保留 `preview.*` 脚本（删除）；包内启动可执行文件 `启动网站.cmd` / `server.mjs`（用户要求删除）；把数据从 `fetch` 改成 `<script>` 加载以支持双击 `index.html`（方案 A 分析清楚但未实施）。
16. **用户在 GitHub 网页上直接改了 LICENSE**（MIT → 0BSD，后又换成 GPL-3.0 全文），造成"自称 MIT、实际 0BSD"的不一致并触发逐字节测试红灯；处理方式是保留用户改动、rebase 自己的提交、再按新许可统一标识。教训：那条"关于页宣称 LICENSE 由本工具生成"的测试必须按 `PROJECT.license` 动态比对，且 GPL 官方正文**没有给使用者留版权行**，断言要按许可证区分（留了位置的必须填、没留位置的必须逐字保持原文）。

**最终状态**

- 站点 **LicenseForge**：Next.js 16 + TypeScript 5.9 + Tailwind 4 静态导出，纯前端、无后端、无运行时外部请求。
