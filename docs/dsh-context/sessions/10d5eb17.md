- 报告（已通过 send_message 交给父会话 39362a4a）固化了以下事实性结论：
  - choosealicense.com：/licenses/ 仅 9 个精选许可证 + appendix 约 40 条对照表，7 种语言（含中文），覆盖非软件与 no-permission；**只有「Copy license text to clipboard」，不填版权信息、无下载/API/CLI**，模板硬编码 `Copyright (c) [year] [fullname]`；agpl-3.0.txt 元数据仍用已废弃的 `spdx-id: AGPL-3.0`。
  - GitHub license picker 官方文档三步流程中**全篇不提供填写年份/版权人的说明**；推断产出仍带占位符（未在真实 UI 复核）。
  - SPDX：权威标识符库（3.29.0），但 Online Tools 无生成器，License Check 只给 4 档匹配度且自述 License List 为 3.28.0（版本漂移），多个 license 页外链自标 `[no longer live]`。
  - JLA：53 个许可证 + inbound×outbound 兼容性检查器 + 五维分类法；但纯查询、无生成/API/CLI、仅英文，兼容性页同时出现新 `GPL-2.0-only` 与已废弃 `GPL-2.0+`。
  - Creative Commons Chooser：8 步问卷、仅 7 个选项、只输出署名标记代码、无 SPDX/API、不生成条款文件。
  - 第三方：FreeLicence（库内仅 5 个许可证，文案过度承诺）、mit-license.org（年份随服务器年、保留 `<copyright holders>`、无下载无 SPDX）、npm license-generator（0.0.13 / 2014，继承占位符与废弃 ID，`-p --project` 疑空转）、licensor（无年份/项目名、无 NOTICE 处理）、Lichen（唯一多许可分区，但自认 SPDX 解析库已失效）、licensekit（实为商业授权 API，非许可证生成器，属同名混淆）。
  - 行业共性问题 TOP 10（各附来源）：不填版权信息丢占位符；GPL only/or-later 与 per-file 声明被系统性忽略；NOTICE/归属清单普遍缺失；废弃 SPDX 标识符仍在流通；极少工具做兼容性/双许可;维护长期停摆、无版本治理；元数据漂移（版本、死链、日期口径）；非英语/中文支持缺失；许可证覆盖面两极分化；文案过度承诺、交互浅。
  - 结论性机会点：版权元数据填齐 + 自动附带 NOTICE 与 per-file 声明头 + 现行 SPDX 标识符（含 only/or-later、WITH 例外）+ 双许可/多许可分区 + 中英双语 + 可下载/可 API——**本次 8 个目标无一同时做到**。

## 结论与遗留

- 达成结论：国际主流工具分工清晰但都不完整——choosealicense/CC 只做「选 + 抄文本」，SPDX 只做标识与校验，JLA 只做比较与兼容性；三大系统性缺陷是版权元数据、NOTICE/per-file 声明、废弃 SPDX 标识符。
- 明确决定：报告明确区分「已实抓验证」与「未核实」；licensegenerator.com 多次 `fetch failed`，标注未核实；licensekit 定性为商业授权服务而非开源许可证生成器。
