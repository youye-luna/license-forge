## 用户诉求

- 以产品竞品调研员身份，用 web_search / web_fetch 实际访问并抓取中文「开源许可证选择与生成」类工具页面。
- 调研 OpenLicr（据称在小众软件论坛 meta.appinn.net 有自荐帖；通过站内搜索或搜 GitHub 上的 openlicr 找到主页/在线地址）。
- 调研国内在线工具站里的 LICENSE 生成器（toolszone.net、tool.lu、菜鸟工具 runoob、OSCHINA 在线工具、bejson、站长工具等），至少找到 3 个真实站点并抓取页面。
- 调研 Gitee/码云 新建仓库时的 license 选择器，以及 Gitee 帮助文档中关于开源许可证的说明。
- 调研中文语境流行的许可证科普内容（阮一峰《开源许可证教程》、图灵社区/InfoQ/开源社等的选择指南），观察其提供的「选择逻辑」。
- 每个目标输出：名称 + URL + 一句话定位；功能清单（支持许可证、是否填版权人/年份、能否下载 LICENSE、有无比较表格、有无中文全文、有无向导问答、是否提及 SPDX、是否涉及专利/商标/贡献者协议、是否只能生成单个 LICENSE）。
- 每个目标给出**具体缺点/短板**并附可核查证据（许可证过少或过时、被篡改/删减的文本、只给模板不给解释、忽略 Apache-2.0 NOTICE、混淆 GPL-3.0-only 与 or-later、无中英双语、无非软件作品、无 API/批量、移动端差、夹带广告等），不确定标注「未核实」，禁止编造。

- OpenLicr 现状定性（本次最重要的可核查发现）：作者自荐公布的 openlicr.com 经 `Resolve-DnsName` 实测 **NXDOMAIN**（openlicr.cn/.net/.io/.app 亦无记录，对照 toolszone.net 正常解析）；[小众软件论坛帖](https://meta.appinn.net/t/topic/79362) 返回 HTTP 404（搜索引擎索引仍在）；[ruanyf/weekly#8656](https://github.com/ruanyf/weekly/issues/8656) 正文可见（0 评论 0 反应，已关闭），作者自述「上线超过半年…无人问津」，宣称 30+ 许可证、对比、场景化选择、一键生成；[GitHub 仓库搜索 total_count=0](https://api.github.com/search/repositories?q=openlicr) 说明非开源、无 API；[Product Hunt](https://www.producthunt.com/products/openlicr) 抓取 403，未核实。→ 所有功能宣称当前不可验证。
- 中文在线工具/选择器实测清单：ToolsZone 文本生成器（12 种、填名字+年份+项目名、可下载、唯一标注 SPDX，但正文全英文、未提 Apache-2.0 NOTICE、无 only/or-later 选项、缺 MulanPSL/GPL-2.0/EPL）；ayalm 开源协议生成器（仅 6 种、全文不提 SPDX、比较表无 NOTICE/商标/贡献者协议维度）；WebUtils（仅 5 种、只有「复制协议」无下载）；Any-Tools 选择器（10 种、比较表被 Pro 付费墙、日本团队中文译文）；toolsnav 选择器（15 种候选、不能生成下载、把 GPL-3.0 标为「适用于网络服务」、使用量无来源）；choosealicense.rustwiki.org（中文界面 + 非软件作品选项 + SPDX 链接，但**正文仍英文**、`[year] [fullname]` 需手改、无表单无下载）。
- 负面证据（六站工具索引均无 LICENSE 生成器）：菜鸟工具 jyshare.com、tool.lu、tool.oschina.net、bejson.com、tool.chinaz.com、toolhelper.cn；OSCHINA 工具仍停留在 JDK6/7、jQuery 插件时代。
- Gitee：[新建仓库](https://help.gitee.com/repository/base/%e6%96%b0%e5%bb%ba%e4%bb%93%e5%ba%93) 与添加 LICENSE 帮助文档仅一句「决定了该开源项目是否对商业友好」，不列清单、不解释差异；[API /v5/licenses](https://gitee.com/api/v5/licenses) 返回 **48 个 SPDX ID**（含 MulanPSL-2.0/1.0、MulanPubL、CERN-OHL、CC-BY、OFL、WTFPL），是中文平台覆盖最广且唯一有 API 的；[MIT 模板](https://gitee.com/api/v5/licenses/MIT) 为英文 + 占位符。
- 中文科普：阮一峰《如何选择开源许可证？》为 2011 年、仅一张图 6 种许可证、无生成；yuan21577/open-source-license-guide 深度对比表把 MPL 判为与 MIT「❌不兼容」（与文件级 copyleft 实际含义不符）、称木兰「与 GPLv3 完美兼容」（未核实）；源译识双语合集与 license-translation 已有十余种中文译本但**无工具接入**。
- 中文工具共性问题 10 条（附证据）：覆盖窄（6/5/10/12 种）；本土许可证缺位（木兰只在 Gitee API 出现）；中文界面+英文正文成常态；SPDX 覆盖不足；only/or-later 与 NOTICE 双缺失；无非软件作品路径；无 API/批量；商业化污染（付费墙、SEO 导流）；个人项目存活率低（OpenLicr 域名+帖+仓库三重消失）；内容硬错（MPL 兼容性、toolsnav GPL-3.0 定位）。
- 机会点：中文全文/官方译文、SPDX 全量+only/or-later 显式化、NOTICE/商标/CLA 提示、木兰一等公民、非软件作品分支、下载+API 批量——中文市场无任一工具同时具备。

## 结论与遗留

- 达成结论：中文市场不存在功能完整的许可证生成工具；「中文界面 + 英文正文 + 5~12 种许可证 + 单页前端」是主流形态，中国本土许可证（木兰）与中文全文译本均未被工具接入。
- 明确决定：会话内尝试委派两个子代理（国内工具站、中文科普内容）**因深度限制被拒**，改为自行完成；对无法实抓的页面一律标注「未核实」。
